# `auto/` — автономный image-first векторизатор (курс v2)

Реализация архитектуры из [`../ROADMAP_v2.md`](../ROADMAP_v2.md). **Контракт:** скрипт САМ
анализирует снимок и векторизует в nlgx/las; эксперт **только проверяет** финал и точечно
разрешает помеченные (FLAG) узлы. Никакого «прохода по файлу со сглаживанием» экспертной трассы.

## Конвейер

```
скан + имя файла + ../mnemonics.json
  meta        приор «ЧТО»: скважина/кривые/глубины/масштаб из имени + словарь мнемоник
  frame   U0  рамка из картинки: колонки треков, верх/низ, depth-калибровка, сетка
  understand U1  сколько ЛИНИЙ, их цвет/толщина/поведение/start-end; оценка переходов масштаба
  scales      A1 (опц., LM Studio): счёт строк линейки = число уровней → n_levels_est
  confidence U2  по линиям: AUTO (разрешимо ~1px) / FLAG (эксперту)
  trace2d     2D-обход штриха по run-графу для AUTO (ловит вершины пиков, не срезает угол)
  emit        understanding.json + overlay.png; при --frame — инъекция трасс → _auto.nlgx(+bck)[+las]
```

## Запуск

```bash
# только понимание + overlay (без рамки)
python -m auto.pipeline <скан.jpg> --out output

# + nlgx/las через ЛЁГКУЮ рамку NeuraLOG (Depth/Scale Axis + слоты, БЕЗ трассы)
python -m auto.pipeline <скан.jpg> --frame <рамка.nlgx> --las --out output

# + прочитать масштабную линейку (число переходов) через A1/VLM (нужен LM Studio :1234)
python -m auto.pipeline <скан.jpg> --ruler
```

Пути — через ENV (`CARROTAGE_DATA`/`CARROTAGE_OUT`/`LMSTUDIO_BASE`) или `--out`; хардкода `F:\nds` нет.

## Файлы

| Модуль | Роль |
|---|---|
| `config.py` | конфиг: пути из ENV, CV-параметры, опц. `prob_provider` (recall-модель) |
| `meta.py` | имя файла → скважина/кривые/глубины/масштаб; mnemonics.json → приоры (чистый Python) |
| `imaging.py` | CV-слой: абс. темнота / цвето-каналы / морф-структура / профили / раны |
| `frame.py` (U0) | автономный детект рамки (треки/верх-низ/сетка/depth↔y) |
| `understand.py` (U1) | счёт линий + свойства + оценка уровней → `Sheet` (первичный артефакт) |
| `confidence.py` (U2) | карта AUTO/FLAG (durable: разрешимое vs информационный пол) |
| `trace2d.py` | 2D-обход штриха по run-графу для AUTO-бакета |
| `scales.py` | счёт переходов масштаба (обёртка A1, LM Studio опц.) |
| `emit.py` | understanding.json + overlay; инъекция в лёгкую рамку → nlgx/bck/las |
| `pipeline.py` | оркестратор + CLI + сводка |
| `prob.py` | адаптер recall-модели → `prob_provider` (опц. torch); поднимает бледные линии |
| `verify.py` | QC результата против изображения (обёртка qc_trace) — «эксперт только проверяет» |
| `feedback.py` | петля «исправленное → повторный анализ»: compare/QC/интейк в корпус |
| `ui/` | локальный веб-UI (stdlib): пути + выбор операции + overlay/JSON |
| `tests/run_pure.py` | чистые проверки (meta, confidence) без numpy |
| `VALIDATION.md` | чеклист: что прогнать и какой ответ ожидать |

## UI

```bash
python -m auto.ui            # http://127.0.0.1:8765 — пути, операции, overlay
```
Операции: тест функции / анализ / векторизация / уточнение (параметры) / проверка (QC) /
обратная связь (исправленное → повторный анализ). Сервер на stdlib — стартует и без numpy
(тяжёлые операции тогда вернут понятную ошибку). Полный сценарий проверок — в `VALIDATION.md`.

## Наша нейронка — нужна?

ДА, но как **high-recall гейт переднего плана** (`prob.py` → `config.prob_provider`), НЕ как
разделитель идентичности (U-Net бинар-маска для разделения линий — закрыт, блобит, §6.6.10).
Recall-ретрейн (fade-aug, §6.6.13) поднимает выцветшие линии (recall 21→84%) — подключается
опционально; без него пайплайн работает на правилах, бледные цветные остаются потолком.

Пакет переиспользует проверенный фундамент из `../digitizer` (формат nlgx, QC, декодер уровней,
export_las) — `__init__.py` кладёт его на `sys.path`. Без torch/scipy/skimage: чистый
OpenCV/NumPy/Pillow; recall-модель подключается опционально через `config.prob_provider`.
