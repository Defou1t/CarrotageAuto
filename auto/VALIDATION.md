# Чеклист проверок: что прогнать и какой ответ ожидать

Чтобы мы понимали друг друга: для каждого шага — команда, что делает, **ожидаемый ответ** (как
выглядит «хорошо») и **красные флаги** (что значит «сломано»). Идём по логическому порядку
(от того, что работает без данных, к полному прогону на боевом скане).

Среда: **Python 3.14 на вашей машине** (numpy/cv2/Pillow). torch — только для `prob` (venv ComfyUI).
Запуск из корня репозитория. Пути к сканам — ваши (`F:\nds\...`).

---

## 0. Чистые проверки (без numpy/данных) — можно где угодно

```bash
python auto/tests/run_pure.py
```
- **Что:** разбор имени файла (оба формата), приоры мнемоник, логика AUTO/FLAG на синтетике.
- **Ожидаю:** `PASS` по всем (parse_filename, expected_curves BKZ→зонды, aliases МБК→MBK,
  confidence: SP→AUTO, перекрытый одноцветный пучок→FLAG bunched, выцветшая→FLAG faint).
- **Красный флаг:** любой `FAIL` — регрессия в чистой логике (чинить до прогона CV).

## 1. UI поднимается

```bash
python -m auto.ui            # → http://127.0.0.1:8765
```
- **Ожидаю:** строка `auto.ui: http://127.0.0.1:8765`; в браузере — панель с операциями.
  «Тест функции → filename» на имени скана возвращает `ok:true` (скважина/кривые/глубины) **без numpy**.
- **Красный флаг:** трейс при старте (сервер на stdlib — стартовать обязан); 403 на свой overlay
  (значит каталог не в allowlist — клади вывод в `--out`/`CARROTAGE_OUT`).

## 2. U0 — рамка из картинки (нужен 1 скан)

UI: «Тест функции → frame», поле image = ваш скан. Или CLI:
```bash
python -c "import auto,auto.imaging as I,auto.meta as M,auto.frame as F; \
rgb=I.load_rgb(r'СКАН.jpg'); m=M.parse_filename(r'СКАН.jpg','mnemonics.json'); \
import json; fr=F.detect_frame(rgb,m); print('треков',len(fr.tracks),'y',fr.top_y,fr.bottom_y,'px/м',fr.px_per_m)"
```
- **Ожидаю:** число треков = числу колонок планшета (обычно 1–3); `top_y < bottom_y` в разумных
  пределах (не 0..H); `px/м` ≈ (bottom_y−top_y)/(глубина из имени) — для 1:200 ориентир ~30–40 px/м.
- **Красный флаг:** треков 0 или абсурдно много (>6); рамка во весь лист (детект провалился —
  это известная точка доводки, шлите overlay, подстрою морфологию/пороги).

## 3. Анализ изображения (U0→U1→U2) — первичный артефакт «понимания»

UI: «Анализ изображения», image + out. Или `python -m auto.pipeline СКАН.jpg --out output`.
- **Ожидаю:** `output/<stem>_understanding.json` + `output/<stem>_overlay.png`. В сводке/JSON:
  - `per_track_line_count` ≈ ожидаемому числу кривых (из имени, поле `expected_curves`);
  - каждая линия: цвет/полоса/поведение (`smooth`/`peaky`)/`n_strokes`/`confidence`;
  - `diag.confidence`: сколько AUTO vs FLAG.
  - на overlay: AUTO-линии цветом по их трассе, FLAG-зоны — жёлтым контуром полосы.
- **Красный флаг:** число линий сильно ≠ ожидаемому (±1 норм); SP не `smooth`; всё подряд FLAG
  (пороги U2 жмут — пришлите JSON, откалибрую `confidence.ConfParams`).

## 4. prob — нужна ли наша нейронка (recall-модель)

```bash
# интерпретатором venv ComfyUI (torch):
python -m auto.prob F:\nds\output\unet_best.pt СКАН.jpg --out output
```
- **Что:** прогон обученной модели → `output/<stem>_prob.png` (хитмап поверх скана).
- **Ожидаю:** на хитмапе подсвечены ВСЕ линии, **включая бледные/выцветшие** (recall-ретрейн их и
  поднимает). `coverage>0.4` — несколько %, не 0 и не весь лист.
- **Зачем:** если модель видит бледные там, где правила их теряют — подключаем её как
  `prob_provider` (UI: поле «Чекпойнт .pt»), и анализ §3 поднимет бледные линии.
- **Красный флаг:** хитмап пустой/сплошной → модель не та или не грузится (проверьте ckpt/torch).

## 5. Векторизация в nlgx/las (нужна ЛЁГКАЯ рамка NeuraLOG)

UI: «Векторизация», image + frame (лёгкий каркас: Depth/Scale Axis + слоты, **без трассы**) + las.
```bash
python -m auto.pipeline СКАН.jpg --frame РАМКА.nlgx --las --out output
```
- **Ожидаю:** `output/<stem>_auto.nlgx` (+`.bck`, +`.las`); в сводке `written` = список вписанных
  кривых; файл **открывается в NeuraLOG** и трассы лежат на чернилах.
- **Красный флаг:** NeuraLOG не открывает/краш → рамка не «родная» (фабрикацию с нуля не делаем);
  кривые не вписаны (`written` пуст) → маппинг линия→слот промахнулся (пришлите understanding.json).

## 6. Проверка (QC) — «эксперт только проверяет»

UI: «Проверка (QC)», nlgx = ваш `_auto.nlgx`. Или `python -c "import auto,auto.verify as V; print(V.verify(r'..._auto.nlgx'))"`.
- **Ожидаю:** per-curve `score` 0..100, медиана и `review`-список кривых <90 (куда смотреть
  эксперту), `suspect_depths` (глубины для клика). Сдаваемо ≈ score ≥ 90.
- **Красный флаг:** «ось глубины вырождена» → рамка без калибровки; score 0 у всех → не та картинка.

## 7. Обратная связь (исправленное → повторный анализ)

UI: «Обратная связь», corrected = исправленный экспертом nlgx, nlgx = наш авто, (ingest — в корпус).
- **Ожидаю:** `compare` per-curve — `median_dx_px` (насколько разошлись) + `worst` (ТОП-глубины
  расхождения = где автомат ошибся); `qc_corrected` — QC исправленного; при ingest — пути в корпусе.
- **Зачем:** `worst`-глубины показывают, что чинить в U1/trace2d; корпус растит приоры/данные модели.
- **Красный флаг:** `median_dx_px` большой по ВСЕМ кривым → системная ошибка рамки/калибровки.
